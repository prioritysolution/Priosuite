==============================================================
Use this as the single source of truth so a new app follows the SAME
architecture, package stack, folder layout, AND page design/style.

How to use in another project:
  1. Copy this file to the new repo root (keep the name or rename to AGENTS.md).
  2. Copy these Cursor rules into .cursor/rules/ :
       - project-architecture.mdc
       - ui-design-system.mdc
       - forms-api-conventions.mdc
  3. Scaffold with the folder map and package.json versions below.
  4. Every new screen MUST use the page shell in section 8 so all pages look the same.

Product: Next.js frontend for cooperative banking (UI + orchestration only).

3) MANDATORY FEATURE FLOW
-------------------------
app/(dashboard)/<domain>/<feature>/page.jsx
  -> container/<domain>/<feature>/index.jsx
       -> Hooks.js          forms, yup, API calls, Redux dispatch, business rules
       -> *Apis.js          HTTP wrappers only
       -> *Reducer.js       optional RTK slice for lists/masters
  -> components/<domain>/<feature>/index.jsx   UI only

Layer rules:
  page.jsx
    - Metadata + render ONE container. No business logic, no API, no Redux.

  container/.../index.jsx
    - "use client"
    - Read cookies (orgId, token)
    - Call hooks; load masters in useEffect
    - Pass props into the presentational component. Keep orchestration thin.

  container/.../Hooks.js
    - Own useForm + yup schema, loading, success dialogs, submit handlers
    - Call Apis; dispatch list data into Redux when needed
    - Export a named hook: useFeatureName

  container/.../*Apis.js
    - Only build { url, bodyData } and call doGetApiCall / doPostApiCall
    - URLs come from utils/endPoints.js — never hardcode full API paths

  container/.../*Reducer.js
    - RTK slice for shared dropdown/table data
    - Register the slice in redux/configureStore.js

  components/...
    - Presentational UI only
    - Use common/formFields (DatePickerField, DropdownField, InputField, …)
    - Do not call APIs or define yup schemas here

5) AUTH AND SESSION
-------------------
Token cookie:  prioBankClientToken
Common cookies: orgId, userBranchId, finId, beg_date, fin_start_date, fin_end_date
Read:  getCookieData()
Write: secureCookieHelper (encrypted)
Dashboard layout redirects to /login if token missing
API 401 -> clear token and redirect to /login (utils/apiConfig.js)


6) API CONVENTIONS
------------------
Base URL: process.env.NEXT_PUBLIC_BASE_API_URL
Bearer token from prioBankClientToken.

endPoints.js:
  getSomething: (orgId) => `${createApi}Org/Module/Action?org_id=${orgId}`

*Apis.js:
  export const getSomethingAPI = async (orgId) => {
    return doGetApiCall({ url: endPoints.getSomething(orgId) });
  };

Hooks.js:
  const res = await getSomethingAPI(orgId);
  if (res.message === "Data Found" || res.message === "Success") {
    dispatch(setData(res.details));   // or res.Data  (APIs vary — check both)
  }

Do not call axios from components or pages.


7) FORMS, DATES, REDUX
----------------------
Always react-hook-form + yup + yupResolver in Hooks.js (not in components).
Shared regex: utils/validationRegex.js
Dates: DatePickerField; store Date at LOCAL NOON (utils/dateHelpers.js) so timezone
       never shifts the day.
API payloads: formatDateForApi(value) from @/utils/dateHelpers
              (or format(date, "yyyy-MM-dd") only on noon-normalized Dates)
Display: dd-MM-yyyy via formatDateForDisplay or date-fns format
NEVER: toISOString().slice(0, 10)  or  new Date("yyyy-MM-dd") for calendar days
Calendar: react-day-picker@8 API (not v9)
Required fields: mark UI with isRequired and mirror in yup
Toasts: react-hot-toast, position top-right
Loading: ClipLoader color="#d7e6f4" size={20}  OR shared Spinner / Skeleton

Redux:
  One slice per feature domain
  Containers/components read with useSelector((state) => state.sliceKey…)
  Do not store entire form drafts in Redux unless that feature already does

8.4 Fields

  Wrapper: h-10 rounded-md border border-input, focus-within:ring-2 ring-ring.
  Disabled: bg-muted/80.
  Dropdown: optionLabelKey from API (often Option_Value, Accout_No, Bank_Name).
  DatePicker: react-day-picker v8, display dd-MM-yyyy.
  Number inputs: max 2 decimals; no spinner arrows (globals.css).
  Radio groups sit in a bordered row: border border-input rounded-md px-3 py-3.

8.5 Buttons

8.6 Tables

11) WHAT AI MUST NOT DO
-----------------------
- Invent a different folder architecture (no services/, views/, features/ unless asked)
- Put API or business logic in app/ pages or presentational components
- Call axios from components
- Hardcode API base URLs
- Commit .env, secrets, or credentials
- Drive-by refactors or unsolicited markdown docs
- Rewrite shared DatePicker / Dropdown unless fixing a real bug
- Install old stacks (Next 13, Tailwind 3, Formik, Zustand, MUI default)

12) MENTAL MODEL
----------------
User opens /investment/investmentClose
  -> thin page
  -> container wires hooks + initial API loads
  -> Hooks owns form + close logic
  -> Apis hit endPoints
  -> component renders the SAME shell + fields/tables
  -> Redux supplies dropdown options if needed
  -> SuccessMessage on save
